# 00 — REGRAS DE USO DA IA

Este arquivo registra regras práticas para usar IA neste projeto sem desperdiçar contexto.

---

## Objetivo

Usar IA como apoio de engenharia, com foco em:

- execução objetiva
- baixo consumo de contexto
- pouca repetição
- decisões rastreáveis
- segurança em produção
- documentação sincronizada

---

## Regras principais

1. Não mandar a IA ler o projeto inteiro.
2. Não mandar a IA abrir pastas inteiras sem necessidade.
3. Não usar prompts gigantes quando um prompt curto resolve.
4. Não manter sessão longa sem resumo.
5. Não pedir várias tarefas desconectadas na mesma conversa.
6. Não pedir refatoração ampla sem objetivo claro.
7. Não usar PDF ou imagem quando texto Markdown resolve.
8. Não pedir execução crítica sem autorização explícita.
9. Não aceitar alteração sem validação.
10. Não considerar tarefa concluída se documentação e código divergirem.

---

## Forma correta de trabalhar

Para tarefas simples:

1. Dizer a tarefa.
2. Indicar arquivo ou módulo.
3. Pedir análise.
4. Aprovar implementação.
5. Validar.

Para tarefas críticas:

1. Pedir diagnóstico.
2. Pedir plano.
3. Revisar riscos.
4. Autorizar execução.
5. Validar resultado.
6. Atualizar documentação.

---

## Gestão de contexto

Se a conversa ficar longa:

1. parar
2. gerar resumo
3. listar decisões
4. listar arquivos alterados
5. listar pendências
6. iniciar nova sessão com o resumo

---

## Regra final

A IA deve economizar contexto, não acumulá-lo.
